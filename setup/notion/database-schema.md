# Notion Database Schema

This document describes the databases and properties included in the Weft Notion template.

The template itself is the primary distribution mechanism for the Notion data model. This document is a technical reference for its database properties and formulas, not an installation checklist.

## Core databases

The core Weft implementation uses:

- Archive
- Projects
- Daily Log
- Error Logs


---

## Formula: Duration (min)

```notion
if(
  or(empty(prop("Start time")), empty(prop("End time"))),
  0,
  dateBetween(prop("End time"), prop("Start time"), "minutes")
)
```

## Formula: Duration (hh:mm)

```notion
lets(
  /* Calculate duration in minutes between end and start times */
  n, dateBetween(prop("End time"), prop("Start time"), "minutes"),

  /* Format minutes to always have two digits */
  minutes, if(
    n % 60 < 10,
    "0" + format(n % 60),
    format(n % 60)
  ),

  /* Format as hours:minutes, or empty string if no end date */
  if(
    empty(prop("End time")),
    "",
    format(floor(n / 60)) + ":" + minutes
  )
)
```

## Formula: Notion URL

```notion
"https://www.notion.so/" + replaceAll(id(), "-", "")
```

| Status                | Select        |
| Daily summary         | Text          |
| Actions               | Text          |
| Documents             | Files & media |

## Formula: Total hours

```notion
round(prop("Total minutes") / 60 * 100) / 100
```

## Formula: Work duration (hh:mm)

```notion
lets(
  totalMinutes, prop("Total minutes"),
  hours, floor(totalMinutes / 60),
  minutes, mod(totalMinutes, 60),

  format(hours) + ":" +
  if(
    minutes < 10,
    "0" + format(minutes),
    format(minutes)
  )
)
```

## Relation troubleshooting after duplication

The current Weft template reproduced correctly in clean-install testing, so relation repair is not part of the normal installation flow.

Notion notes that duplicated workspace content can occasionally require relation repair. If the duplicated Weft databases do not behave as described, verify these relation targets first:

| Database | Property | Expected target |
|---|---|---|
| `Archive` | `Project` | duplicated `Projects` database |
| `Archive` | `Daily log` | duplicated `Daily Log` database |

If either relation points to the source workspace, is disconnected, or no longer targets the duplicated database:

1. Open the affected database.
2. Open the relation property's settings.
3. Select the corresponding database inside the duplicated Weft workspace.
4. Restore the reciprocal relation when the property is intended to be two-way.
5. Confirm that dependent rollups resolve again.

Do not change unrelated property names or types. After repairing the relation, rerun:

```powershell
python -m installer preflight
```

The installer should resolve the four duplicated Notion resources and their required property mappings uniquely before installation continues.
