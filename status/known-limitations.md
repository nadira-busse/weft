# Known Limitations

This document describes the current technical boundaries of Weft and the capabilities that are not yet implemented.

---

## Current Baseline

Weft has working archive, search and context-retrieval workflows with explicit contracts, stable archive identity and runtime evidence from Make and Notion.

The limitations below describe what this implementation does not yet provide.

---

## Limitations

### 1. No Change-Aware Persistence

Stable identifiers prevent duplicate archive records under the current write model.

Immutable field guards also prevent protected context, such as project ownership, from being silently reassigned.

These controls protect identity and ownership, but they do not detect unchanged content or skip unnecessary updates.

Not implemented:

* payload hashing
* content hashing
* snapshot comparison
* skip-on-equal behavior

The system does not yet distinguish between:

```text
same identity + same content
same identity + modified content
```

---

### 2. Flow-Bound Validation

Weft uses explicit schemas and payload contracts, but validation is currently implemented separately at each workflow boundary.

Not implemented:

* centralized schema validation
* a reusable validation service outside Make
* global contract enforcement across workflows

---

### 3. Deterministic Search, Not Semantic Search

Search is currently based on explicit filters and constrained lookup behavior.

Supported search criteria include:

* conversation ID
* project
* query
* date range

Requests may also set a result limit.

Not implemented:

* semantic search
* embedding-based retrieval
* fuzzy matching
* inference-based expansion

Users must provide explicit search input.

---

### 4. Limited Context Composition

`get_context` retrieves archived context from persisted records.

The current flow returns retrieved archive content in its stored block-based structure, using `clean_text` blocks.

It does not automatically build a full working context from multiple archive records.

---

### 5. Non-Deterministic Metadata Is Contained

Some metadata fields may be generated or derived, such as:

* summaries
* insights
* action items
* labels or categories

These fields may vary across executions if generated by AI.

The archive source remains the primary record and is not controlled or modified by derived metadata.
